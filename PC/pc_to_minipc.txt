## Phase 1: Host-Level Physical Network Configurations
Run these commands directly on the raw host machine terminals (outside of Docker) to establish the physical subnets.
## 1. Configure the Mobile Hotspot over Wi-Fi

   1. Turn on your mobile phone's hotspot.
   2. Connect your Laptop to the hotspot network.
   3. Connect your Mini PC to the hotspot network.
   (If headlessly controlling the Mini PC via the temporary USB management cable, run this from the Mini PC terminal):
   
   sudo nmcli device wifi rescan
   sudo nmcli device wifi connect "YOUR_HOTSPOT_NAME" password "YOUR_HOTSPOT_PASSWORD"
   
   4. Extract the wireless IP footprints allocated by your phone for later use:
   * On Mini PC: Run ip a show dev wlp4s0 (Our target was: 10.119.16.181)
      * On Laptop: Run ip a show dev wlan0 or wlp... (Our target was: 10.119.16.49)
   
## 2. Configure the High-Speed LAN Backbone Cable
Ensures the heavy point cloud streams pass between the two robot computers without choking the phone's Wi-Fi.

* On the Jetson Orin NX Host Terminal (manas@manas-desktop):

# Authorize local Docker container layers to output graphics to your monitor
xhost +local:docker
# Force the wired LAN port to a manual static IP block
sudo nmcli connection modify "Wired connection 1" ipv4.method manual ipv4.addresses 10.0.0.1/24 ipv4.gateway "0.0.0.0"
sudo nmcli connection up "Wired connection 1"

* On the Mini PC Host Terminal (spring@spring):

# Force the secondary computer-to-computer LAN port link onto the static subnet
sudo nmcli connection modify "Jetson Ethernet" ipv4.method manual ipv4.addresses 10.0.0.2/24 ipv4.gateway "0.0.0.0"
sudo nmcli connection up "Jetson Ethernet"
# Configure the dedicated LiDAR hardware port (eno1) into Link-Local safety fallback mode
sudo nmcli connection add type ethernet con-name "Ouster_LiDAR" ifname eno1 ipv4.method link-local ipv4.addresses "" ipv4.gateway ""
sudo nmcli connection up "Ouster_LiDAR"

## Phase 4: Establishing the Multi-Machine Zenoh-DDS Tunnel
Since mobile hotspots explicitly block default ROS 2 UDP Multicast traffic over the air, we deploy symmetrical Zenoh containers to funnel the data through stable TCP channels.
## 1. Flush any hanging network port blockers (On the Mini PC Host)

sudo pkill -f zenoh-bridge-dds
docker rm -f $(docker ps -a -q --filter ancestor=eclipse/zenoh-bridge-ros2dds:latest) 2>/dev/null || true

## 2. Launch the Master Zenoh Router Hub (On the Mini PC Terminal)
We listen on 0.0.0.0:7447 to bridge data cleanly across both your internal LAN line and the wireless Wi-Fi link at the same time:

docker run --rm -it --net=host \
  -e ROS_DISTRO=humble \
  -e ROS_DOMAIN_ID=42 \
  eclipse/zenoh-bridge-ros2dds:latest \
  --listen tcp/0.0.0.0:7447

## 3. Launch the Symmetrical Zenoh Client Peer (Locally on your Laptop Terminal)
Open a local terminal prompt on your laptop (do not SSH out) and run this container to catch the incoming over-the-air TCP stream:

docker run --rm -it --net=host \
  -e ROS_DISTRO=humble \
  -e ROS_DOMAIN_ID=42 \
  eclipse/zenoh-bridge-ros2dds:latest \
  --connect tcp/10.119.16.181:7447
